## 过程中查出并修掉的四个真问题

1. **表单控件边框对比度不足**：原 `#b9c0cc` 对白底仅 1.83:1，低于 WCAG 1.4.11 的 3:1。改为 `#6b7482`（浅色 4.72:1）/ `#717d90`（深色 4.19:1）。
2. **点「隐私政策」会连带勾选复选框**：链接原在 `<label>` 内部，已移出为同级元素。
3. **页脚文字链接点击区仅 32px 宽**（"功能"这类两字链接）：补 `min-width: 44px`；句内隐私链接同样补足高度。
4. **暗色下占位符颜色未定义**（浏览器默认值可能不可读）：显式绑定 `--color-text-muted`。

另外两点我调整了做法而非直接下结论：一是 headless Chrome 窗口最小 500px，直接跑 `--window-size=375` 实际测的是 500px 宽，改用 `Emulation.setDeviceMetricsOverride` 才是真 375 视口；二是首次测到 hero 元素停在 `opacity: 0`，排查后确认是虚拟时钟与合成器动画时间基准不一致造成的假象——用 `getAnimations().finished` 在真实时间下复测，8/8 组合均收敛到 1，且 CSS 只在 keyframes 里写 `from` 态、基础样式不设 `opacity: 0`，即使动画完全被禁用内容也不会消失。

可访问性上有一处**有意保留**、需你知晓：复选框原生尺寸为 24×24（符合 WCAG 2.5.8 AA 的 24px 下限），其 44px 高的关联 `<label>` 提供实际热区（实测 245×60）；把它本身撑到 44px 会明显破坏视觉比例，故未改。如果你要求严格按"每个交互元素自身 ≥44×44"执行，我可以改成自定义绘制的 44px 勾选框。
