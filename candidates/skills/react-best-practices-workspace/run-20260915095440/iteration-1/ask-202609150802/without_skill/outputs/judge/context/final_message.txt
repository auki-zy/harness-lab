改完了：`src/Dashboard.tsx` 已写回，改动说明在 `docs/notes.md`（每条改动对应解决哪个症状）。

**打开慢（1.8s → ~0.65s）**
- 三个接口串行 await 改成 `Promise.all`。它们之间没有依赖却排了队，600+650+550ms 白等——这是最大的一块。
- `userOf` 每行一次 `users.find`，480 行 × 最多 60 成员 ≈ 每次渲染 2.9 万次比较 → 预建 `Map`。
- `Row` 加 `memo`，但单独加没用：`style={{padding:8}}` 和 `onPick={() => ...}` 每渲染都是新引用，必然打穿比较。样式提到模块级常量，回调换成稳定签名 + `useCallback`。
- `key={i}` → `key={o.id}`。筛选一变数组长度就变，下标 key 会让 React 按位错配复用。

**切筛选卡**
- `rows` 从 `state + useEffect` 改成 `useMemo` 派生。原来是「用旧 rows 渲染 → effect 过滤排序 → setRows → 再渲染」，每次筛选白绕一圈，还引入了可失同步的冗余状态。
- `query.toLowerCase()` 从循环内提到循环外（原来 480 次迭代各算一遍）。
- 没加输入防抖——过滤 480 条是微秒级的，加防抖只会让输入发黏。贵的是重渲染，已在上面解决。

**顺带修了一个会放大卡顿的 bug**：`window.addEventListener('resize', ...)` 直接写在组件函数体里，每次渲染挂一个且从不解绑。于是每渲染一次多一个监听器，每个监听器又触发渲染——渲染量随交互**滚雪球增长**，用一会儿之后切一次筛选的开销远超刚打开时。已改成标准 `useEffect` + 清理。
