## 主要问题与改法

**打开慢（~1.8s）** — 根因是三个接口串行 `await`（600+650+550ms），而它们互不依赖。改成 `Promise.all` 后降到约 650ms，基本就是这一处。

**切筛选卡** — 是多个原因叠加，按影响排序：

1. **resize 监听写在渲染体里且从不清理** — 每渲染一次就多挂一个监听，永不移除。输入几个字符后就叠了几十个监听，这本身就是卡顿主因，也是内存泄漏。已移入 `useEffect` 并配清理。
2. **`userOf()` 每行一次线性查找** — 480 行 × 60 用户 ≈ 每次渲染 28,800 次比较。改成 `Map` 索引。
3. **筛选/排序放在 effect 里写回 state** — 派生数据不该存 state，每次筛选白跑一轮渲染。改成渲染期 `useMemo`。
4. **`Row` 完全无法复用** — 每行的 `style` 对象和 `onPick` 闭包都是新引用，加上没 `memo`，导致每次输入都全量重渲染 480 行。三处一起修了。
5. `key={i}` → `key={o.id}`；输入加 `useDeferredValue` 保响应。

## 两点需要你知道的取舍

**`.sort()` 我保留了，没换 `toSorted()`。** 最佳实践里有这条，但它的目的是避免就地修改原数组——而这里 `.sort()` 接在 `.filter()` 后面，`filter()` 本来就返回新数组，不存在这个问题。而 `toSorted()` 需要 ES2023，这个工作区没有 `tsconfig.json`，我无法确认编译目标和浏览器版本，换了有编译失败风险、收益为零。理由写在 notes 里了。

**`useDeferredValue` 需要 React 18+。** 同样因为没有 `package.json`，我无法确认 React 版本。如果项目还在 17，这一处要换成防抖或直接去掉——去掉后其余优化独立成立。
