改完了。`src/Dashboard.tsx` 已写回，说明在 `docs/notes.md`。

**首屏慢** —— 三个接口原来串行 await，耗时相加 ≈1.8s：
1. 改 `Promise.all` 并发，总耗时降到最慢那个 ≈650ms，一次批量提交。
2. `useState(window.innerWidth)` 改惰性初始化，不再每次渲染都读一次布局。

**切筛选卡** —— 主要成本是 480 行全量重渲染：
3. `rows` 从「effect + setRows」改成 `useMemo` 渲染期派生，省掉每轮变化多出的一整轮渲染，也消掉两份可能不同步的状态。
4. `query.toLowerCase()` 提到循环外，原来 480 行各算一次。
5. 成员查找 `users.find` → `useMemo` 建的 `Map`，原来每次渲染 480×60 ≈ 2.9 万次比较。
6. `Row` 加 `memo`，并把两个每次渲染都新建的 prop 稳定下来：`style={{padding:8}}` 提成模块常量，`onPick` 改 `useCallback`。这是卡顿的主因。

**顺带的两个 bug**：
7. `key={i}` → `key={o.id}`，排序/筛选重排行序时按位置复用 DOM 容易张冠李戴。
8. resize 监听原来写在函数体里、每次渲染挂一个且从不移除 —— 无限累积，且每次 `setWidth` 又挂新的，形成放大循环；改成 `useEffect` 挂载一次 + cleanup 移除。

**没做的**：列表虚拟化（480 行 DOM 不是瓶颈）和输入防抖（筛选本身很轻，防抖反而让结果滞后于输入），理由写在 notes 里了。

一点需要说明的：这个工作区只有 `src/Dashboard.tsx`，没有 `package.json`、tsconfig 或测试，所以这些改动**只做了静态审查，我没能跑类型检查或测试**。其中第 8 条改动前是真实的行为缺陷（监听器泄漏），但如果你那边有测试断言了某些时序细节（比如数据分三批渐进出现），并发改造后行为会变成一次性出现 —— 建议在有工具链的环境里跑一遍确认。
