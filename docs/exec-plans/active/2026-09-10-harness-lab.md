# 计划：harness-lab 能力评测实验室（v1）

## 目标

让"能力是否值得采纳"变成可复现的数据流程：候选池 + 自包含试用（`mock` / 受控对比）+ 机读结果 + 台账页面 + 明确决策（adopt / hold / reject / retry）。

## 范围（v1）

1. 能力归口本仓库：未采纳在 `candidates/`，已采纳在 `adopted/`（当前：`adopted/skills/frontend-design`）；
2. 数据：`evals/schema.md`（规范）+ `tags.json`（标签表）+ `capabilities.json`（登记）+ `trials/*.json`（试用）；
3. 试用方式 `controlled` / `mock`（默认）；**评测材料必须自包含在本仓库**（`live` 已退役，仅为旧记录兼容）；
4. 评测**不自造引擎**：技能 → skill-up、子代理 → promptfoo、MCP → 内置协议探针，各自的 bridge 只负责"报告 → trial"；`tools/aggregate.mjs` 聚合为 `evals/results/app-data.json`；
5. 台账页面（Vite + React + TypeScript + AntD）：列表 + 搜索 + 标签筛选 + 两级详情（能力记录 → 试用详情）+ dev 下的「发起评测」弹窗。

## 明确不做什么

- 不做服务端 / 数据库 / 登录；页面只读本地生成的 JSON，不暴露原始 JSON、不做在线编辑；
- 不依赖外部真实项目：`live`（真实项目使用）不再作为常规做法（历史记录保留）；
- 不重复造评测引擎：判定规则只有一处（`tools/lib/trial-record.mjs` 的 `decide()`），工具选择按能力类型固定；
- 不装模板产品内容（内置技能、安装器、子代理/MCP 声明目录）——能力用 `harness-tool add` 从本仓库装。

## 验证路径

- `npm run data` 生成 `evals/results/app-data.json`（含待确认标签告警）；
- 五件套全绿：`npm run typecheck / lint / test / build`（当前 26 用例）；
- 三套工具各跑通一次（离线自检用 stub 引擎 / 演示 MCP server；真实调用见进度日志）；
- build 把证据复制进 `dist/evidence/`；dev 实测 `/`、评测规范、证据文件 200，未登记路径 404；`/api/eval/status` 报出三个工具可用性；
- 人工过一遍：首页 → 搜索 → 标签筛选 → 能力记录 → 试用详情 → 打开证据 → 发起评测。

## 风险与 blocker

- 样本仍少：4 个能力各 1 条试用，"多能力 / 多试用 / 多维度筛选"刚有数据，还不够压；
- 工具链依赖外部环境：skill-up 的引擎要本机 agent CLI（当前用 stub 代跑）、promptfoo 走 `npx` 需要网络与缓存——桥接必须都能"只导入报告"兜底；
- 试用成本：就算是 `mock` 也要人写用例与检查方式——别为评测造无用任务；
- 指标漂移：结论随模型/环境变化，trial 必须带模型与日期。
