# QUALITY_SCORE.md

这份文档用来跟踪仓库是在变强还是变弱。

## 评级标准

- `A`：验证通过、可读、稳定、边界执行到位
- `B`：可用，只有少量缺口
- `C`：部分可用，存在明显混乱或不稳定
- `D`：损坏、不安全，或结构上说不清楚

## 简化实验日志

| 日期 | 移除的组件 | 结果 | 决策 |
|------|-----------|------|------|
| 2026-09-10 | 单文件静态看板 `dashboard/index.html` 与 `evals/results/dashboard.json` | 被 Vite + React 台账替换，信息表达明显更清楚；那份聚合产物已无人消费 | `keep removed` |
| 2026-09-10 | 模板产品内容（`skills/`、`agents/`、`mcp/` 与安装器）与脚手架文档（`BOOTSTRAP`/`FRONTEND`/`CODE_STANDARDS` 等 14 份 + `docs/references`、`docs/generated`） | 与评测无关；必要的工程约定收进 `ARCHITECTURE.md`，仓库文件数 97 → 64，路由表与文档引用不再指向仓库外的东西 | `keep removed` |
| 2026-09-10 | "已采纳能力放模板"的做法 | 能力改由本仓库统一存放（`candidates/` → `adopted/`）；模板侧同步移除能力目录，项目用 harness-tool 按需安装。少一处副本，来源/许可/证据只有一份 | `keep removed` |
| 2026-09-10 | 自造的评测引擎（`tools/trial.mjs`、`tools/executors/`、`task.json` 用例格式、`HK_TRIAL_*` 执行器开关） | 换成成熟工具 + 薄桥接：技能用 skill-up、子代理用 promptfoo、MCP 用协议探针。三种能力都真跑出了 trial，而自造引擎只覆盖"技能"一种且需要自己维护判定代码 | `keep removed` |
| 2026-09-11 | 试用详情「这次是怎么跑的」单独压暗一档的标题样式（`.sheet--muted`） | 同一层级的模块标题长得不一样，读起来像"次要内容"，与它承载的信息量不符 | `keep removed` |
| 2026-09-11 | 「客观指标」表里替人下"哪个更好"的措辞 | 指标表退回只讲事实（谁比谁多多少），"哪一版更好"收进独立的「系统小结」块并写明依据规则——两件事不再混在一处 | `keep removed` |
