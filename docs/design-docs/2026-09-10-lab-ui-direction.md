# 设计决策：能力台账的界面方向（2026-09-10）

- Owner：仓库维护者
- 更新触发：台账首页或详情记录的视觉/文案方向发生改变时

## 问题

实验室的数据（试用、A/B 对照、人评、证据）本身是机读 JSON，但**判断**发生在人脑里。旧版看板的问题不是不好看，而是**说不清**：卡片上写"最近 trial / 人评 / 结论 / 证据"，脱离上下文看不懂 A 和 B 分别是什么、谁更好、为什么这么判。

所以这一版的目标是：**在不了解评测流程的前提下，5 秒内看懂任何一条记录的结论，并能往下追到证据。**

## 决策

### 1. 隐喻：实验室台账，不是仪表盘

采用「台账（ledger）」而不是「dashboard」：一行一条记录，纵向排列、发丝线分隔、数据一律等宽字体。仪表盘暗示实时监控，而这里的真相来源是历史记录；台账的阅读方式（从上往下核）正是实际的用法。

### 2. 色板（冷灰绿纸底 + 印章色）

| token | 值 | 用途 |
|---|---|---|
| `--ink` | `#17191B` | 正文与主分隔线 |
| `--paper` | `#EEF0EC` | 页面底色（冷灰绿，避开"奶油+衬线+陶土"的默认套路） |
| `--sheet` | `#F7F8F5` | 台账纸面、卡片底色 |
| `--slate` | `#5C6670` | 次级文字、说明 |
| `--petrol` | `#1D4E48` | 主色：可点、选中、对照条胜出侧 |
| `--seal` | `#AE3B2C` | 需要你处理的事（待确认标签） |

结论语气色单独一组：采纳 `--jade #1D6B57`、挂起 `--ochre #8F6414`、放弃 `--seal #AE3B2C`、重试/未评估灰。颜色只做强化，印章里的字本身就能读懂。

### 3. 字体分工

- 中文正文：系统无衬线（PingFang SC / 微软雅黑…），不做 Web 字体请求，离线可用；
- 数据：等宽（Cascadia Mono / Consolas…）——能力 ID、日期、体积、文件路径、标签取值；
- 眉标（eyebrow）：等宽大写小字，用于栏目标题，替代大号装饰标题。

字体本身不是主角，**「哪里是数据、哪里是说明」用字体区分**才是目的。

### 4. 签名元素：A / B 对照条

实验室唯一真正的仪器就是受控对照，所以把它做成最显眼的元素：一条横杆，左半 A（不加载能力）、右半 B（加载了能力）；**人评给出"哪版更好"时**（快捷档只给个选择也算），赢的那半被点亮并打勾，下面一行写清结论与体量差别。没有人评、没跑过试用、或者人评没做选择时，杆子保持灰色并直说（"还没有人评" / "人评只给了赞/踩，没有比较两版"），不假装有结论。

这是这一版唯一"敢"的设计动作，其余部分保持安静：没有渐变、没有大圆角、没有装饰性编号。

### 5. 结构即信息

- 行首色条 = 结论语气（采纳/挂起/放弃/重试），不是装饰；
- 详情抽屉的顺序 = 阅读顺序：结论 → 怎么用 → **每条试用一块（块内是它自己的二级详情与证据）** → 来源与标签；
- 证据文件只写「文件名 + 它是什么 + 打开」，路径藏在 `title` 提示里（早先版本同时摊开仓库相对路径，看不出哪条证据对应哪次试用）。

## 修订（2026-09-10，第一轮体验反馈后）

按实际使用后的反馈做了一轮**减法**，判断标准是"这条信息会不会帮人下结论"：

| 反馈 | 处理 | 理由 |
|---|---|---|
| 风险面标签没用 | 删掉 `risk` 维度（`evals/tags.json` + `DIMENSION_ORDER`），并加了一条守卫用例防止维度漂移 | 一个人自用、能力都来自可信上游，风险面没有区分度，只是筛选噪音 |
| 原始数据入口不该透出 | 去掉「原始数据」按钮，`/evidence` 也不放行 `evals/results/app-data.json` | 页面就是读数入口；暴露 JSON 只会让人绕过结论直接看原始字段 |
| 台账说明太长 | 说明压成一句话；规模事实由三格卡片改成一行文字 | 首次使用只需要知道"点一行看完整记录" |
| 想先看到两条试用，再看各自详情 | 详情里删掉"最近一次 + 历史时间线"的重复结构，改成"试用记录（N 次）"，**每条一块**，块头是记录摘要（印章 / 日期 / 任务 / 试用方式），块内是该次的二级详情与证据 | 原来的时间线只有摘要、没有详情，等于把一半信息藏起来了 |
| 证据区复杂且不知道证据在哪 | 证据跟着各自的试用块走，只显示文件名 + 它是什么 + 打开 | 证据本是"这次试用"的证据，挂在试用块下才说得清归属 |
| 选中标签 hover 看不清（绿底绿字） | 选中态 hover 只压深底色、保持白字（`.facet__chip--on:hover`） | 这是纯 CSS 特异度 bug：`.facet__chip:hover` 的 `color` 盖过了选中态的白字 |
| 界面整体还是太满 | 去掉列头、页脚、行内来源/模型、详情里的三段事实清单与"本地位置/原始路径"两行 | 信息并没有丢，只是挪到了"需要时才看"的位置（详情块内、末尾一行、JSON 与 `SOURCE.md`） |

减法之后的固定约束（写进 `docs/product-specs/capability-ledger.md`）：**首页只放能帮人下结论的信息，证据与路径都跟着它所属的那次试用走。**

## 修订（2026-09-10，第二轮反馈）

| 反馈 | 处理 | 理由 |
|---|---|---|
| 已采纳的能力要能一键装上 | 台账行与详情「怎么用」显示安装命令 + 复制按钮；命令是数据字段（`capabilities.json` 的 `howToUse`），不在组件里写死 | 能力内容现在只存在 lab，看到结论的下一步就是"装上试试"，复制是最高频动作 |
| chip 的维度名和取值区分不明显 | chip 改成 `维度 \| 取值` 两段式：维度名在浅灰绿小格里（等宽小字 + 右侧分隔线），取值单独一段、用正文色 | 原来两段都是灰字，看不出哪个是分类哪个是值 |
| 台账行内容重复 | 去掉行上的状态词（印章已表达结论）和人评整句（对照条下面那行已表达同一件事） | 同一信息只说一次；行内只留能改变判断的内容 |
| 试用详情太长，想先看列表再看单次细节 | 详情拆成两级抽屉：一级列"试用记录"（一次一行），点「看详情」开二级抽屉看那一次的条件、人评、指标、依据与证据 | 一级抽屉的职责是"给结论 + 给索引"，细节按需下钻；多条试用时不再互相挤占视线 |
| 能力内容该放哪 | 能力（技能/子代理/MCP）统一放 lab：候选在 `candidates/`，已采纳在 `adopted/`，项目侧用 harness-tool 安装；模板不再携带能力内容 | 模板生成的项目不该带一堆用不上的能力文件；来源、许可与试用证据集中一处才好维护 |
| 安装命令太长记不住 | harness-tool 增加短入口 `harness-tool add <name>`（默认从 lab 的 `adopted/` 找、类型自动识别），页面与文档一律用短形式 | 页面上的命令是要"看一眼、复制、粘到项目里"的，长度直接决定它会不会被用 |
| 人评不该配"证据模块" | 证据块改成按评判方显示：`judge` 含 `llm` / `auto` 才出现「对比证据链」；只由人评的试用换成一句说明（产物在「条件」里可打开） | 人评是主观判断，用"证据"框起来会假装它是客观结论；证据链的意义在于能复核可复现的评判 |
| 首页统计条像一句白话 | 改成三项统计：小字标签 + 等宽数字（已采纳用玉色、为 0 的项压暗），发丝线分隔，逐项带 `title` 说明 | 数字是要被"扫"的，标签是要被"认"的；两者不该同字号同颜色 |
| 说明文案在"没有 A/B"的试用上说错话 | 二级抽屉里那句说明改成按**试用方式**取（受控对比 → 产物在「条件」里；模拟场景 → 产物在仓库里；真实项目使用 → 项目在别处，只留结论） | 原来一律写"两版产物在「条件」里可打开"，而真实项目试用既没有 A/B、产物还只是一堆 `.tsx` 源码，浏览器打开只能看文本 |
| 评测不该依赖外部真实项目 | 试用加 `kind` 维度：`controlled` / `mock`（默认）/ `live`；决策规则改成"**≥1 次可复核试用通过**即可 adopt"（第三轮改为"连续两次通过"，见下），`live` 降为加分证据 | 真实项目常在别的仓库，产物和证据链都留不下来；评测材料必须自包含，否则结论无法复核 |
| 两次试用的记录串了 | **两级结论分离**：台账行与详情顶部显示**能力级**结论（来自 `status`，试用中才退回最近一次试用），试用列表与试用详情显示**该次**结论；详情顶部的 eyebrow 写成「结论（能力级）」并注明"每次试用的结论在下面"；能力级不再重复显示"最近一次人评"（那属于试用记录）；`verdict.reason` 只许讲这一次 | 之前把"受控对比通过 + 两次人评赞 → 采纳"写在某一条 trial 的 `reason` 里，打开那条试用就像同时看到了两次试用的评价——记录之间不隔离，读者无从判断哪句话属于哪一次 |
| 行内那句成了"结论"，不是"说明" | 能力数据分两个字段：`description`（一句话说明：干什么的，行内显示）与 `summary`（一句话结论：值不值得用，详情结论区显示）；行内不再写结论（印章已表达） | 台账行是"认东西"的地方——先要知道这是什么；结论用印章一眼扫过就够，混在一句里反而两头都不清楚 |
| 搜索能命中的东西太多 | `matchesQuery` 收窄成**只匹配名称与说明**；来源、标签、试用内容不再参与（要按它们找就用筛选） | 搜索框命中来源仓库名或某次试用的描述，会让人以为"这条能力跟那个词有关"；筛选才是分类的入口 |
| 对照条在重复自己 | A/B 两半改成短标签（`A 不加载` / `B 加载`，完整含义进 `title`），**选中侧只打 ✓ 图标**（不再写"人评更好"），caption 只留结论（"人评选了 B"）+ 体量差别；删掉 full 变体里那行重复两半含义的图例 | 同一条信息在段内、caption、图例里出现三遍；图标承担"选中"这一件事就够了 |
| caption 整句都不需要 | **删掉 `beam__caption`**：杆子只做一件事——用 ✓ 标出人评选中的那半；没人评 / 人评没选时杆子转灰、中缝改虚线，完整说法放 `aria-label` 与 `title`（无障碍不丢信息） | 行内已经有印章（结论）、说明、meta（试过几次），再挂一句"人评选了 B"就是第四次说同一件事；体量差别在试用的「客观指标」表里 |
| 详情模块名不明确、还带 eyebrow | 抽屉标题只留能力名 / 试用标题（去掉 eyebrow）；一级抽屉固定五个模块：**结论 → 采纳/放弃原因 → 如何使用 → 试用记录（卡片）→ 来源与标签**；试用记录从列表行改成卡片 | 模块名就是导航：原来"结论（能力级）""怎么用""试用记录"命名不齐、还夹着 eyebrow，读者得自己猜边界；列表行在只有一两条时太单薄，卡片能放下"哪次/怎么试的/结论"三件事 |
| 结论模块里塞了三样东西 | **结论只放一个印章**（采纳 / 挂起 / 放弃 / 重试 / 未评估）；口语结论、一句话说明、元信息全部撤掉——"这是什么"留在台账行，"为什么"由下一个模块（采纳/放弃原因）回答 | 印章本身就是结论，旁边再写"可以采纳"是同义反复；说明与元信息属于别的模块，挤在结论里只会让人以为它们也是判断 |

## 修订（2026-09-10，第三轮：评测在页面上跑 + 换掉自造引擎）

| 反馈 | 处理 | 理由 |
|---|---|---|
| 试用不该跑在当前会话里，页面只展示结果 | 页眉加「发起评测」弹窗（**仅 dev**）：选工具 → 填输入 → 跑 → 轮询日志 → 自动落账 → 「刷新看台账」；评测在服务端子进程里跑，输出写 `.trial-runs/<id>.log` | 会话是一次性的，评测要能被重复发起、被记录、被别人复查；页面只做展示，动作走接口 |
| 三种能力形态不能共用一套评测法 | 弹窗按类型分三段：技能 → skill-up、子代理 → promptfoo、MCP → 协议探针；每段只显示自己需要的输入，`/api/eval/status` 报告各工具是否可用 | 技能的"带/不带能力"是提示层对照、子代理是输出格式约束、MCP 根本没有对照——硬套一种做法只会得到假结论 |
| 自造引擎维护不起 | **删掉 `tools/trial.mjs` 与 `tools/executors/`**，判定与记账收敛到 `tools/lib/trial-record.mjs`，评测交给成熟工具 | 自造引擎只覆盖技能一种，还得自己维护判定与执行器；成熟工具自带用例格式、报告与裁判，我们只需要写薄桥接 |
| 采纳门槛太松 | `decide()` 改成：B 侧没全过 → `reject`；工具自身报错 → `retry`；B 全过**且此前已有一次通过** → `adopt`；否则 `hold` | 一次通过可能只是运气；"连续两次"才配得上"采纳"，同时不动第一条记录的结论 |
| 人评会不会被自动化顶掉 | 人评保留为附加信号（`humanReview` + `judge` 里的 `human`），不参与上面那几条分支 | 客观检查判"做没做对"，人评判"值不值得"；两者混在一个公式里会互相污染 |

## 修订（2026-09-11，第四轮：试用详情以对照为主 + 系统小结）

| 反馈 | 处理 | 理由 |
|---|---|---|
| "试用记录详情中重点不明显，预期是明确看到前后对比结果，产物等……其他可有可无" | 二级抽屉重排成**对照优先**：① 结论 + A/B 前后对照板（含"打开产物"）→ ② 客观指标（全部维度）→ ③ **系统小结：哪一版更好** → ④ 评审人 + 人评入口 → ⑤ 这次是怎么跑的 → ⑥ 为什么这么判 → ⑦ 证据链 | 试用要回答的是"带了这个能力之后到底变成了什么样"，所以先给两版并排的结果与产物，背景信息往后放 |
| "对比规范要增加更多维度……比如 token 用量，会话时长，步骤" | `measures` 扩到 12 类维度（token 四档 / 耗时 / 轮次 / 工具调用与构成 / 花费 / 产物大小 / 静态检查 / MCP 工具清单），页面逐行列出，**拿不到的不摆空行**；差异只说事实（"B 比 A 多 3%，越少越省"） | 做对了也可能更贵、更慢、更啰嗦；这些维度是"权衡"的证据，先摆出来，不写进判定 |
| "客观指标对比完成后，系统总结一下 AB 的优劣，给出系统推荐结果" | 新增独立一块**「系统小结：哪一版更好」**：分栏说清 A / B 各自好在哪、差在哪，再给一句推荐（正确性优先 → 人评优先 → 总 token / 耗时 / 工具调用 / 产物大小，差 5% 以内算持平，各有胜负就如实说），**并把依据规则原样印在下面** | 只有数字、没有结论，读的人还得自己算一遍；但结论必须可追溯，所以规则写死在 `systemSummary()`、页面照抄依据，且明确"只判这一次对照、不改采纳判定" |
| "这次是怎么跑的"标题 ui 同其他标题一致 | 删掉 `.sheet--muted`（连同样式），所有模块标题同为 `sheet__title` | 同一层级的模块标题长得不一样，会让"背景信息"看着像另一种层级；信息层级应该靠**顺序**表达，不靠字号与颜色 |

## 修订（2026-09-11，第五轮：发起评测收成一张表单）

| 反馈 | 处理 | 理由 |
|---|---|---|
| "发起评测内改为 Antd Form 表单"、"能力：Input，提示词：textarea" | 弹窗改成 `Form`：第一格 **能力**（`Input`）、第二格 **提示词**（`Input.TextArea`，4 行、带字数），`layout="vertical"`、不显示必填星号 | 两格本来就是"填一个名字 + 可选写一段任务"，用 Form 表达后 label、控件、校验、提交语义都是现成的，不用自己拼 `Space.Compact` |
| "下方提示去掉" | 删掉常驻提示行；只在**点了也跑不了**时弹一条 Alert（入口没开 / 名字对不上 / 没有可用引擎），并把「提交」置灰 | 常驻提示是"每种输入都念一遍会发生什么"，读的人第二次就把它当背景噪音；改为只在**阻断**时说话，信息密度反而更高 |
| "开始评测放在右下角关闭旁边，更名为提交" | 页脚右下角：`关闭` 在左、`提交` 在右（跑完多一颗 `刷新台账`），原来的主按钮从输入框右侧挪进页脚 | 主按钮贴着输入框会让人以为"这一格是按钮的一部分"；放进页脚就是标准的"填完表单 → 提交"，而且和「关闭」构成一组退出/确认 |

## 修订（2026-09-11，第六轮：试用记录改表格、证据链改左右查看器）

| 反馈 | 处理 | 理由 |

## 被否掉的选项

- **三列卡片网格**：比较型数据横排更难对齐，且容易退化成通用后台卡片墙。
- **奶油底 + 衬线大标题 + 陶土点缀**：AI 生成的默认长相之一，与"实验室台账"这个主题没有关系。
- **纯黑底 + 单一荧光强调色**：适合演示，不适合长时间核对数据。
- **给栏目编号（01 / 02 / 03）**：这里没有真实序列，编号只会是装饰。
- **把成本门槛写进 `decide()`**（"B 必须比 A 更省才采纳"）：成本是权衡不是门槛——"多花 10% token 但少写一半代码"该不该采纳是人的判断；改成在详情里给对照级小结，让人带着成本信息自己决定。
- **让「系统小结」替人下采纳结论**：小结只回答"这一次哪一版更好"，采纳仍由客观通过率与"连续两次"决定；两件事混在一处，等于用一次对照的性价比去盖过能力级证据。
